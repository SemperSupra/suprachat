## 2. Core Architecture: How AI-Enabled IDEs Interface Systems

Modern AI coding environments (e.g., Cursor, Windsurf, Copilot Workspace, Claude Code, Antigravity) orchestrate four primary subsystems through an event-driven, tool-calling agentic loop.

```
+-------------------------------------------------------------------------------+
|                             Model Reasoning Core                              |
|                    (Cloud / Local LLM via Structured Tools)                   |
+-------------------------------------------------------------------------------+
                                      ▲
                                      │ Tool Calls / Results
                                      ▼
+-------------------------------------------------------------------------------+
|                       IDE Agent Host & Tool Dispatcher                        |
+-------------------------------------------------------------------------------+
         │                               │                               │
         ▼                               ▼                               ▼
+--------------------+         +--------------------+         +--------------------+
|   Editor Buffers   |         |   Terminal Host    |         | Repos & FileSystem |
| (In-Memory Diffs)  |         | (PTY / ConPTY Shell)|         |  (LSP / Ripgrep)   |
+--------------------+         +--------------------+         +--------------------+
```

### 2.1 Editor Buffers vs. On-Disk Files
* **The Conflict**: Direct file-system writes overwrite unsaved operator edits and destroy the local undo stack (`Ctrl+Z`).
* **The Solution**: 
  - IDEs expose an in-memory document model (e.g., `WorkspaceEdit`, `ITextBuffer`).
  - Edits generated by the AI are staged as **virtual diffs** (side-by-side or inline decorations: additions in green, deletions in red).
  - The operator explicitly chooses **[Accept]** or **[Reject]**, keeping the undo stack continuous and safe.
  - Granular patch formats (Search/Replace blocks, unified diffs, or Tree-sitter AST surgery) minimize token round-trips.

### 2.2 Paired Terminal Host & The Self-Healing Execution Loop
* **Pseudo-Terminal Abstraction**: Shell commands are executed through a real pseudo-terminal (ConPTY on Windows, POSIX `/dev/pts` on Unix).
* **Buffer Sanitization**:
  - Raw shell output contains ANSI control sequences (`\x1b[31m`, cursor repositioning) that confuse LLM tokenizers. The bridge strips ANSI sequences prior to context injection.
  - Secret scanning scans stdout/stderr for API keys or tokens before staging output into model prompts.
  - Output buffers are clamped (e.g., 256 KiB) to prevent context exhaustion.
* **Closed-Loop Self-Healing**:
  $$\text{Code Edit} \longrightarrow \text{Execute Test/Build} \longrightarrow \text{Capture Error Trace} \longrightarrow \text{Model Diagnoses \& Generates Fix} \longrightarrow \text{Rerun}$$

### 2.3 Repository Indexing & Semantic Retrieval
* **Three-Tier Context Aggregation**:
  1. **Lexical**: Sub-millisecond regex search across files using embedded `ripgrep`.
  2. **Semantic**: Vector embeddings over chunked codebase files for conceptual matching.
  3. **Structural / LSP**: Querying Language Server Protocol endpoints (`textDocument/definition`, `workspace/symbol`, compile diagnostics) for deterministic code navigation without LLM hallucinations.

## 3. SupraChat Cockpit Findings & Solutions

During the GUI overhaul of `MainWindow.axaml` and `WorkbenchView.axaml`, several critical UI/UX and runtime findings were resolved:

### 3.1 Hardcoded Colors vs. Stock OS Theme Compliance
* **Problem**: The Reverse Tunnel page and workbench cards had hardcoded `#FFFFFF` backgrounds and `#4B5563` text colors. In Windows Dark Mode, Avalonia defaulted `TextBlock` foregrounds to white, producing invisible **white-on-white text** and jarring neon contrast.
* **Solution**:
  - Eliminated all 33 hardcoded hex colors.
  - Adopted Avalonia Fluent `DynamicResource` system brushes:
    - `{DynamicResource SystemControlBackgroundAltHighBrush}` (Adaptive card surface)
    - `{DynamicResource SystemControlBackgroundChromeMediumLowBrush}` (Card containers / pills)
    - `{DynamicResource SystemControlForegroundBaseHighBrush}` (Primary text)
    - `{DynamicResource SystemControlForegroundBaseMediumBrush}` (Secondary text)
    - `{DynamicResource SystemControlForegroundBaseLowBrush}` (Dividers & borders)
  - UI now complies 100% with stock Windows Light Mode, Dark Mode, and High Contrast settings.

### 3.2 Vector Iconography vs. Text Emojis
* **Problem**: Text emojis (`▶`, `⏹`, `🧹`, `🔍`, `✨`) render inconsistently across platforms and look unpolished in enterprise environments.
* **Solution**:
  - Implemented crisp `StreamGeometry` vector icons in `App.axaml` (`IconPlay`, `IconStop`, `IconClear`, `IconCopy`, `IconSend`, `IconTerminal`, `IconShield`, `IconRefresh`, `IconCode`, `IconExternal`, `IconCheck`, `IconWarning`).
  - Rendered via `<PathIcon Data="{StaticResource ...}" />` across all buttons and actuators.

### 3.3 WebUI & Desktop Plan Synchronization
* **Problem**: Clicking between Personal and Work workspaces in the embedded ChatGPT WebUI (`ChatView`) did not update the desktop cockpit plan indicator.
* **Solution**:
  - Connected `ChatView.NavigationCompleted` to inspect URL changes (detecting `workspace=`, `/team/`, `/biz/`).
  - Transformed `EntitlementPill` into an interactive actuator allowing one-click plan mode review and explicit operator confirmation.

### 3.4 Wire-Level Entitlement & Work Spend Protection
* **Implementation** (`EntitlementGuard.cs`):
  - Strict route pinning: `/v1/responses` with personal subscription tokens (`chatgpt.tokens.use.direct`).
  - Automatic stripping of outbound Work-pool billing headers (`OpenAI-Organization-Work-Pool`, `X-OpenAI-Work-Context`).
  - Mandated `store: false` zero-retention invariant.
  - Fail-closed refusal of `WORK` intent without an unexpired, confirmed operator work lease.

## 4. Hardware Verification vs. Headless CI Qualification

* **Native Desktop Hardware (Session 1)**:
  - Live qualification executed by operator Mark E. DeYoung against running PID 41328 via `test-uia.cmd` achieved **100% pass across all 3 sample batches**.
  - Verified 6,454 UI Automation nodes, 364 walker count, 540–660ms traversal time, and zero provider errors.
* **Headless CI Runners**:
  - Public GitHub Actions Windows Server 2025 runners operate in a headless service session without an interactive `WinSta0\Default` desktop.
  - This occasionally causes Avalonia Win32 window-station initialization races (`UIA_HOST_PROCESS_EXITED_BEFORE_SEMANTIC_PEERS`).
  - Confirmed: Avalonia Win32 UIA provider is fully healthy on real native hardware.
