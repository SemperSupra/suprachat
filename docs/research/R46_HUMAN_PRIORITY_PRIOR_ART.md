# R46 — Human-commanded concurrent sessions: global prior art, source survey, adoption decision

Date: 2026-11-22. Status: **source-reviewed candidate architecture**, not product acceptance. Execution authority: [SupraChat #195](https://github.com/SemperSupra/suprachat/issues/195), #19 multi-session UX, #38 W7 durable recovery, #39 W8 audience identity; private #2 DLE. Scientific comparator: Model Spelunker #265. No new session registry or scheduler.

## Requirement and observed ChatGPT runtime boundary

Humans, automation and agents participate concurrently in **the same authenticated canonical session** with distinct credentials, capabilities and UX/DX. The verified human operator can interrupt, give alignment/intent/guidance and request stop/resume with higher scheduling priority than lower-priority worker input. A role string, prompt content, visual button, voice transcript or synthetic input cannot *authenticate* a human or bypass policy. Human intent preempts future **candidate actions** immediately through a durable control-epoch increment; the actual worker side effect may be in-flight and its cessation/rollback is independently observed.

Prior ChatGPT introspection experiments established: tool capability is separate from authorization and evidence; model sessions do not expose the hidden runtime/scheduler, internal state, token budget or first-party backend. ChatGPT's instruction precedence is not an external programmable preemption API, and a ChatGPT browser session cannot be externally hijacked to apply guidance. Build this priority control in SupraChat's own admitted session core, not as a system-prompt trick or undocumented ChatGPT endpoint.

## Multilingual concept sweep and source-backed comparison

Languages queried: English, German, Chinese, Japanese, Korean, Spanish and Thai. Searches covered intervention and resumption, human priority, durable state, collaboration, actor mailboxes, checkpoints, role impersonation and cross-device UI. Source proof and external background are separate: German Microsoft HITL documentation, Japanese OpenAI Agents SDK guide, Chinese multi-agent workflow descriptions and Korean human stop/restart examples reinforce the same broad patterns, but do not independently qualify a codebase as a safe drop-in controller. Thai-language results were not sufficient to establish a distinct battle-tested implementation; do not manufacture one.

### Additional Nov 22 source discovery — Google's CAGE governance reference

`google/cybernetic-agent-governance-engine@d05c7b95c65e0654291f5ee40ec8020c1f14876f`, Apache-2.0, is a **reference architecture explicitly not an officially supported Google product**. Its `README.md` describes a deterministic gateway between agent/tool actuation, single-use signed seals, barrier-epoch logic, two-phase governance, tamper-evident signed receipts and an independent `proof/` verifier that does not import the implementation. The architecture rechecks mutating stages *after* human approval because authority and world state can change during review.

This is an unusually close comparator for our W8/W9+R46 tool-effect authority fence, but **not yet battle-tested or recommended as a full replacement**: its own open POAM records explicitly call out WebAuthn human approval assertions not being verified (`POAM-2026-210`), single-maintainer review risk, and an accepted development/production boundary. Treat a trustworthy human identity as a separate acceptance gate. **Next independent source-safe bake-off**: verify `NoDirectBind`, required fresh seal/epoch, revocation between human approval and tool effect, first-outcome signed refusal receipt, and independent trace verifier under current frozen code. Only adopt the narrow reusable verifier/signed-seal primitive if an external oracle beats current W12/W9 contracts. Do not introduce a second gateway in the default control plane merely because the project demonstrates a policy pipeline.

## Primitives: select an established protocol, retain the proven one-writer state authority

- **State**: `SessionId`, authenticated `PrincipalId/Audience`, `SessionRevision`, `ControlEpoch`, `RunId`, `ToolLeaseId`, `ContextDigest`, `EventSequence`, `OperationId`, `GrantId`, `PendingGuidanceDigest`, `CancellationReceipt`, `WorkcellOwner`.
- **Data structures**: bounded per-session append-only event journal with hash/digest references; CAS version/epoch; stable idempotency outcome map; per-actor scoped grants; priority control mailbox (bounded human intervention lane, not unbounded arbitrary commands); per-worker observed epoch; immutable snapshots and device-specific view projections. Optional CRDT shared *drafts*, never authoritative control.
- **Transitions**: `RUNNING → PAUSE_REQUESTED → QUIESCENT → RESUME_REQUESTED → RUNNING`, or `RUNNING → STOP_REQUESTED → STOPPED`, with `UNKNOWN` and `FAILED` when cancellation cannot be independently confirmed. Human `GUIDE` is a pause request plus a canonical versioned guidance reference. `PAUSE_REQUESTED` is **not** `QUIESCENT`.
- **Ordering and atomicity**: high-priority authenticated human control admitted ahead of low-priority *future* work, even if a worker is streaming; single writer persists epoch/state/event atomically before ack; future side-effect proposals must present matching epoch, version, scoped actor grant and live owner binding. Never hold the ledger lock during network/tool I/O.
- **Algorithms**: optimistic CAS and monotonically increasing fencing tokens; first-outcome idempotent replay; per-session actor/event mailbox; cooperative stop with bounded deadline, observed safepoint and explicit `UNKNOWN` on failed cancellation; reconciling in-flight effects before replay; normalized deterministic state transition reducer; bounded stream subscriptions with gap detection and resume cursor.
- **Invariants**: verified human > automation/agent **within allowed action scope**; no audience label self-authenticates; no simulated human preemption bypasses OS identity or revocation; stale epoch never effects a tool; held session continues to be readable by all authorized audiences; one authoritative context regardless of device; human guidance does not delete audit history; no accepted tool result before durable commit; no false stop/rollback claim; cross-session isolation; no automated upgrade from tool request to approval.
- **Properties to test**: safety (no unauthorized effects, no double-commit, no lost human override), liveness (bounded human-input acknowledgment and no deadlocks), fairness (other sessions progress; nonhuman work eventually resumes when humans release), linearizability of epoch update, crash consistency, replay determinism, idempotence, role spoof rejection, revocation, UI/accessibility parity, provider/model-stream equivalence and observable divergence.

## Three-audience UX/DX

**Human:** persistent high-priority guide/pause/stop controls, differentiated request/confirmed states, accessible names/shortcuts and screen-reader announcement; context-preserving suggestions, speech and touch input when separately permissioned. A phone may initiate a guidance event while a desktop displays the same session's tool state. The human should never have to be the message bus.

**Automation:** stable typed read/subscribe/propose/cancel-request API and idempotent operation IDs; same session/event cursor and receipts; cannot fabricate the human bootstrap or user approval.

**Agent:** async typed event stream (AG-UI-compatible where qualified), `HUMAN_INTERVENTION` epoch change, new context/guidance ref, clear `YIELD/REPLAN/STOP` requirements, tool-scoped permits and stale-epoch refusal; no preference inferred from a model's own message.

## Decision and near-term bake-off

**Adopt mature components where their scope fits; implement only the narrow missing control semantics in existing SupraChat core.** AG-UI 1.0 event vocabulary/.NET SDK and CopilotKit can reduce front-end integration cost; LangGraph/Temporal/Agents SDK supply harness-specific HITL/cancellation patterns; retain existing SupraChat W6/W9 SQLite single-writer authoritative ledger with W8/W12 scoped identity work. A full Temporal/CopilotKit rewrite and one-size-fits-all CRDT arbiter are disproportionate and risk dual-authority drift.

Parallel qualification:
1. **AG-UI native .NET ↔ browser interoperability**: source-pinned event mapping, pause/guide/stop/resume, stream catch-up, partial event and corrupted payload negatives; compare with thin in-house JSON projection.
2. **Three-audience single-writer policy reducer**: #196, synthetic high-priority human request increments epoch and fences stale proposals; no production claim until host/W9 integration.
3. **Assistive/mobile UI**: Android Foundry #9 human control accessibility and typed automation/agent views; no raw sensor input granted.
4. **Durable host integration**: W7 epoch checkpoint, W8 verified actor/session/capability, W12 revocation; no new repository.
5. **Independent chaos/HIL**: delayed/hung tools, interruption during effect, crash before/after commit/ack, stale/replay keys, two human devices, one automation and one agent, cross-session fairness, queued human bursts, capture/revocation, real HIL when admitted.

**Sequential integration:** freeze semantic schema and safety contract → independent peer-review of role/epoch/stop semantics → integrate with W9/W8 single writer and tool owner → run deterministic property/fault matrix → qualify live local/remote clients and accessibility + same-task continuation → admit physical/protected provider execution → package release. If AG-UI fails the exact integration oracle, retain the narrow transport mapper; do **not** fork AG-UI or duplicate the core ledger.

### Scope limits
No public CI or source-level demo can prove ChatGPT first-party backend preemption, human identity, real provider cancellation, external side-effect reversal, signed approvals, physical HID or production admission. No private credentials, OAuth/browser cookies, sensitive raw content or private evaluation corpora in public GHA. Preserve every historical failure/receipt and source lineage for bake-off.
